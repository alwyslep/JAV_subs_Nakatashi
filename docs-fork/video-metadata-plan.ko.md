## 0. 한 줄 결론

자막을 열면 영상이 이미 같이 열리고, 그 영상 안에 **인물 관계가 적힌 일본어 줄거리**가 있으며,
읽을 도구(**TagLibSharp**)는 이미 의존성에 들어 있습니다. 그리고 그보다 더 좋은 것 —
번역기가 만든 **작품별 화계 가이드북과 27,136행짜리 용어집** — 이 이미 디스크에 있습니다.
Nakatashi는 이것을 **다시 뽑을 게 아니라 같은 DB를 열어 읽고, 사용자의 수정을 되돌려 쌓아야**
합니다.

| 파이썬 변경 위치 | ~~`feat/register`에 올리고 main과 병합하지 않는다~~ → **양쪽 브랜치가 DB 작업을 똑같이 갖는다** (2026-07-30 개정, 사유는 아래) |
| `%APPDATA%`의 나머지 | **옮기지 않는다.** settings·logs·quota·model_probe·webview는 공유 대상이 아니다 |

| `NameList` 주입 | **세션 한정.** 배우 이름은 작품마다 다르므로 전역 기록은 다른 작품 편집 시 오염된다 |

### 개정 (2026-07-30) — 파이썬 변경은 `main`에도 올라간다

"병합하지 않는다"는 결정은 **구현이 그 근거를 무너뜨렸습니다.** 원래 논거는 "두 브랜치 차이가
프롬프트 본문뿐이라 충돌이 없다"였는데, 단계 2·4가 끝난 뒤 차이는 프롬프트가 아니라 **DB 계약**이
되었습니다. 실측한 `main`의 상태:

| `main`이 갖지 못한 것 | 실제 결과 |
|---|---|
| `termdb.py`의 `pinned` 인식 (**언급 0건**) | `save_series()` 재수확이 편집기가 고정한 표기를 **덮는다.** `JavTerms.Pin` 기능 자체가 무의미해진다 |
| `paths.py`, `guidebook.py`의 SQLite 경로 (**언급 0건**) | 이관 완료된 가이드북 42행을 **못 읽는다.** 편집기가 고정한 관계 노트가 번역 런에 닿지 않는다 |

DB 쪽은 이미 이관·`ALTER`가 끝났으므로 이것은 이론적 위험이 아닙니다. 그리고 **`.venv`가 있는
쪽은 `srt-translator`(main) 워크트리뿐**이라 — `srt-translator-register`에는 없습니다 —
실제로 실행되는 것이 main입니다.

그래서 두 커밋(`paths` + `pinned`)을 **`main`에 체리픽**했습니다(`257a65e`, `e47d788`, 충돌 0).
A/B 기준선은 그대로입니다: `main`은 `c752e12`(방향+등급 프롬프트)를 유지하고 `feat/register`는
종전 프롬프트를 유지하므로, 두 브랜치의 유일한 차이는 여전히 `meta.py`의 `PRESCAN_PROMPT`와
`pornify.txt`입니다. 검증: 자가검증 17종 전부 통과, `paths.*()`가 종전과 동일한 `D:\` 경로를
반환, `guidebook.load()`가 SQLite에서 42행을 읽음.

## 2. 실측 — 임베드 태그

**자막이 있는 영상 293편** 무작위 표본. atom 이름은 mutagen으로 직접 확인:

| ffmpeg 키 | MP4 atom | 보유율 | 실제 내용 |
|---|---|---|---|
| `title` | `©nam` | **99%** | 일본어 원제 |
| `album` | `©alb` | 99% | 품번(57%) **또는** 시리즈명 |
| `artist` | `©ART` | **94%** | 배우명, 쉼표 구분 |
| `comment` | `©cmt` | 92% | **일본어 줄거리 150~240자(57%)** / 품번(27%) / 빈 값(9%) |
| `genre` | `©gen` | 88% | 166종 어휘 |
| `date` | `©day` | 88% | 발매일 |
| `album_artist` | `aART` | 88% | 레이블 |
| `director` | `©dir` | 63% | 감독명 |
| `description` / `synopsis` | `desc` / `ldes` | 36% | **`©cmt`의 한국어 MT** |
| — | `covr` | ~75% | 커버 아트 (mjpeg) |
| `encoder` | `©too` | 68% | **태거 세대 판별자** |
| `copyright` | `cprt` | 3% | 레이블 |
| `url`,`titleJa`,`catalogedAt` | `----:com.javtag:*` | 3% | freeform |
| **챕터** | — | **0%** | 하나도 없다 |

### ★`©cmt`는 일본어, `desc`는 한국어 — 둘 다 있다

```
ROE-476  ©cmt : 長く教職に従事する優香は、受け持つ生徒たちを卒業へ導くため、日々厳しい指導にあたっていた…
         desc : 오랫동안 교직에 종사하는 유카는 받아들이는 학생들을 졸업으로 이끌기 위해…
         ©gen : 人妻・主婦, 女教師, 辱め, 単体作品, 熟女
         ©dir : 加州夏      aART : マドンナ
```

**LLM에 넣는 것은 반드시 일본어(`©cmt`)** 입니다. 한국어 쪽은 기계 번역이라 품질이 낮습니다
(위 예의 "받아들이는 학생들" = 受け持つ 오역).

### 관계 정보가 실제로 들어 있다는 증거

| 품번 | 태그가 말해 주는 관계 |
|---|---|
| `ROE-225` | `©cmt`: 「**兄嫁である義姉**」 → 형수↔시동생 |
| `ROE-150` | `©cmt`: 「夫亡き後、**一人息子の修一**を育ててきた真希」 → 홀어머니↔아들 |
| `ROE-476` | `©gen`: `女教師` + 「長く教職に従事する優香」 → 여교사↔졸업생 |
| `SDNM-013` | `©cmt`: 「**旦那が喜ぶなら**」…人妻・相原さん → 남편 공인, 부부↔제3자 |

`CLAUDE.md`가 *"관계 정보는 한국어 SRT가 만들어지는 순간 파괴된다"*고 적어 둔 그 정보가
영상 파일 안에 살아 있습니다.

> 물려주면 배역이 통째로 달라 오히려 화계를 망가뜨린다. 작품 단위로 누적되어야 하는 것은

Nakatashi가 데이터를 쌓을 때도 이 구분을 지켜야 합니다.

## 5. 이름 규칙 — 음차 강제, 의미번역 금지

**사용자 결정:** 이름 사전에 들어가는 것은 이름이므로 **음차(발음)**여야 하고,
**의미 번역은 절대 불가**합니다.

| 원문 | 올바름 (음차) | 틀림 (의미번역) |
|---|---|---|
| `鈴の家りん` | 스즈노야 린 | ~~린의 집 인~~ |
| `早川夏美` | 하야카와 나츠미 | ~~빠른 강 여름 아름다움~~ |
| `蝦原` | 에비하라 | ~~새우하라~~ |

### 이 병은 이미 데이터에 있다

**① 한국어 MT 태그(18%)가 감염:**

```
ABF-108  ©ART : 린의 집 인, 아베 토모히로, 이세동 우치무라, …   ← 鈴の家りん 의 의미번역
```

**② 레거시 `terminology/MIDE.json`에도 위반 존재:**

| 항목 | 판정 |
|---|---|
| `黑田`→쿠로다, `杏梨`→안리, `铃木酱`→스즈키 짱 | 음차 ✅ |
| `裤子酱`→**바지 짱** (裤子=바지) | 의미번역 ❌ |
| `章鱼哥`→**문어 형** (章鱼=문어) | 의미번역 ❌ |
| `稳重先生`→**안정 씨** (稳重=안정) | 의미번역 ❌ |
| `벨벨`→`벨벨` | 원문 자리에 한국어. 쓰레기 ❌ |

> 이 항목들이 현역 `jav-terms.sqlite`에도 넘어갔는지는 **이관 전에 확인해야 합니다**
> (`migrated_json=1`이므로 넘어갔을 가능성이 높습니다). 확인 방법은 8장 단계 0.

**③ 방어는 부분적으로 존재** — `meta.py::_ja_performers()`가 한글이 든 배우명을 드롭합니다
(주석에 `蝦原`→`새우하라` 사례). 단 **배우명에만** 걸리고 용어집에는 안 걸립니다.

### 설계 규칙 (타협 없음)

1. **이름의 소스는 원문 표기뿐.** 한글이 포함된 `©ART` 값은 이름으로 쓰지 않는다.
2. **음차 변환 결과만 저장**한다. LLM에 시킬 때는 "발음만, 의미 번역 금지"를 프롬프트에 못박는다.
3. **AI 프롬프트에 넣는 인명은 원문 그대로.** 모델이 한자를 읽는 편이 망가진 한글을 읽는 것보다 낫다.
4. 기존 용어집 항목은 **정제 대상**이지 그대로 쓸 물건이 아니다.
5. Nakatashi가 terms에 쓸 때도 같은 게이트를 통과시킨다 — **오염원이 하나 더 생기면 안 된다.**

### 7-3. 가이드북 이관 대상 — `jav-register.sqlite`

`terms`가 아니라 **`register` DB에 새 테이블**로 넣습니다.

| 후보 | 판단 |
|---|---|
| `jav-terms.sqlite` | ✗ 키 단위가 다르다 — terms는 전역/시리즈, 가이드북은 작품 |
| **`jav-register.sqlite`** | **✓ 같은 화계 도메인, 이미 `code`(품번) 컬럼을 쓴다** |
| 새 DB | ✗ 네 번째 파일. 경로 관리만 늘어난다 |

결정적 근거: `runs`와 같은 DB에 있으면 **"사람이 고쳐 고정한 가이드북이 실제로 화계 붕괴율을
낮췄는가"를 SQL 한 줄로 물을 수 있습니다.** 그것이 "서로 쌓아 더 나은 번역"의 측정 수단입니다.

```sql
CREATE TABLE IF NOT EXISTS guidebook(
  code       TEXT PRIMARY KEY,      -- 품번. guidebook.py 의 _key() 와 같은 정규화
  text       TEXT NOT NULL,
  pinned     INTEGER NOT NULL DEFAULT 0,
  source     TEXT NOT NULL DEFAULT 'prescan',  -- pinned|prescan|stored|user|se
  updated    TEXT NOT NULL,
  updated_by TEXT NOT NULL DEFAULT ''          -- 'translator' | 'nakatashi'
);
```

- `regdb.py` 헤더의 "여기 쌓는 것은 지표다" 주석은 **갱신해야 합니다** — 원칙(관계는 작품
  단위로만)은 그대로지만 파일의 역할이 넓어집니다.
- `pinned` 우선순위와 "프리스캔은 고정본을 덮지 않는다"는 규칙은 **그대로 유지**합니다.
- 이관은 43개 JSON을 읽어 INSERT하는 1회성 스크립트. **원본 JSON은 지우지 않고 남깁니다**
  (되돌릴 길).

### 단계 5 — 이름 역검증 ✗ **만들지 않기로 함 (2026-07-29). 측정 근거 아래.**

계획은 "한국어 자막의 인명을 원문과 대조해 의미번역 사고를 탐지"였습니다. 만들기 전에

**A) 의미번역 의심 — 0건.** 영상 메타의 한글-오염 인명(`린의 집 인` 류)이 한국어 자막에
그대로 나오는 경우가 **하나도 없었습니다**. 당연합니다 — 자막은 태거의 MT 패스가 아니라
번역기나 제3자가 만든 것이라 오염 경로가 다릅니다. 이 탐지는 영원히 안 걸립니다.

**B) 표기 불일치 — 93건이지만 전부 노이즈.** 편집거리 1 매칭이 한국어에서는 못 씁니다.
음절 블록 하나가 자모 하나 차이로 **완전히 다른 낱말**이 되기 때문입니다:

| 용어집 정본 | 자막에서 걸린 것 | 실제 |
|---|---|---|
| 어머니 | 할머니 | **다른 사람** |
| 아가씨 | 아저씨 | 다른 낱말 |
| 카메라맨 | 카메라 | 다른 낱말 |
| 자지님 | 자지 | 일반어 |
| 유노 씨 | 유리 씨 | 다른 사람 |

게다가 **정본 등장률이 7.1%** 입니다(자막 179개 × 정본 7,361회 중 524회). 즉 "정본이 자막에
없다"가 **정상 상태**(그 작품에 그 인물이 안 나옴)라, 부재를 근거로 삼는 탐지는 성립하지
않습니다.

> **결론:** 결정론적 역검증은 만들면 노이즈 생성기가 됩니다. LLM 패스로는 가능하지만
> (`유리 씨`와 `유노 씨`가 같은 사람인지 판정하는 일은 정규식이 못 합니다) 새 비용이

#### 정직한 결론: 이것은 생산성 기능이 아니라 정확성 기능이다

같은 8편을 두 번 돌린 결과가 **고정가능 1→3건** (1회차)과 **2→1건** (2회차)입니다. 1차가

- 방향 오류가 실행 가능한 유일한 작품에서 **2건 중 2건** 잡혔습니다. 드문 사고가 아닙니다.
- `src`를 채우는 것 자체는 작동합니다 — `타키모스 씨` → `宅本さん`을 원문 줄에서 정확히
  읽어냈습니다.

즉 단계 7은 고정을 **더 많이** 하게 만든 것이 아니라 **틀린 고정을 하지 않게** 만들었습니다.
고정률을 올리려면 1차가 방향을 맞게 고르도록 만드는 것이 먼저입니다 — 그것이 다음 판단거리입니다.

#### 남은 판단거리

1. **방향을 되돌릴 것인가.** 2차는 `ko`가 틀렸다는 것까지 알고 있고, 옳은 표기가 `wrong` 목록에

   뒤집는 것이라 `BuildReplacements` 앞으로 2차를 옮겨야 합니다 — 구조 변경입니다. 지금은
   **미선택 + 이유 표시**로 사람에게 넘깁니다.
2. **`PreferredLanguages`를 넓힐 것인가.** `ja` 하나로 65.3%이고, 원어 아무거나면 99.5%입니다.

   그냥 꺼집니다(의도된 안전장치).
3. **분할(A/B) 자막.** `NSFS-046`이 그 경우인데, 조각 하나는 절반만 커버해 일치율 50% 미만으로
   거부됩니다. 설계대로의 안전한 실패이지만 그 5%에서는 기능을 잃습니다.
